# DevFlow AI 项目介绍与证据口径

本文用于准备简历及项目演示；以实际参与内容和当前验证结果为准，使用前可根据目标岗位删减。

## 简历描述草稿

**DevFlow AI｜多 Agent 软件研发助手**

基于 Python、FastAPI、PostgreSQL、SQLAlchemy 与 Docker 构建面向代码 Issue 的多 Agent 系统，围绕任务执行、受控工具和证据验收组织研发流程。

- 设计 Task / Run 持久化与 Supervisor 路由，协调 Explorer、Planner、Coder、Verifier 完成代码探索、方案规划、修改与检查；结合租约、预算和部分失败恢复管理执行过程。
- 建设受控工具及验收链路，区分公开检查、可信侧独立评测和人工审核；持久化执行记录与证据，限制工作区和工具权限。
- 实现带来源的长期记忆候选、审核与停用，以及显式的同仓库跨任务召回；记忆内容保持未核实状态，记忆辅助任务受独立评测边界约束。
- 封装测试命令与修改范围检查 Skills，复用现有 Harness、Policy 和 Verifier 工具链；实现受控 RSI 实验账目与预算通道原型，通过双进程、双数据库角色和模型桩构造演示记录候选、用量及淘汰结果。

## 证据与边界

- 历史 Click #3019 有一次真实任务正式通过及人工审核文件记录；Click #3084 两次尝试未完成。前者不代表多任务稳定性或可靠成功率。
- Memory、跨任务召回、Skills 的主要证据为构造数据和隔离测试；尚无充分的真实多任务复用和效果对照。
- RSI 演示使用构造任务、版本引用与模型桩；没有真实候选改进实验、独立对照评测或自动晋升。`accepted` 和自动循环保持禁用，不能写成系统已自主进化。
- 并发恢复中，不同 Worker 使用同一恢复键会收到创建冲突；测试验证不得重复创建，但不能据此声称常驻恢复循环已自动处理所有竞争异常。
- 部分新增迁移尚未应用到现有业务库；不要为准备演示擅自迁移案例库或修改历史 Run。
