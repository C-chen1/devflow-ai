# 独立验收边界（待实现）

## 目标与适用范围

针对 Click #3019 等可信任务，修复流程执行公开基线和公开测试；独立评测端在补丁产生后执行其私有验收。隐藏验收源码、参考修复和评分逻辑不进入 Agent 上下文、工具回执、公开 Artifact 或工作区。公开测试通过不能代替私有验收通过。

## 控制端与执行端

可信控制端持有经过核验的任务包和私有验收材料，固定任务包版本、基准提交、公开命令、目标测试、环境要求及私有验收版本。修复端只能获得公开部分；控制端接收修复产物并将其送入独立执行环境。结果关联 Task、Run、补丁摘要、任务包版本和评测版本，记录通过、失败或不可用；不可用不得当作通过。公开结果应避免暴露私有测试内容和可重构答案的详细诊断。

控制端必须先核验补丁与 Run 的关联，再在固定基准上应用该补丁进行验收。验收前后需验证受保护测试材料与控制配置的完整性；若身份、完整性、运行环境或结果归属不明，结果为不可用。补丁、输入和结论的正式绑定及 Run 终态必须由可信控制端在提交时再次核验，不能仅信任 Agent 自报。

## 安全边界与当前限制

目前 `read_file` 限制路径和注册命令白名单只约束经 Harness 发出的请求。pytest 会执行目标仓库中的 Python 代码，而该代码可以使用当前进程账号的文件和网络权限；把隐藏文件放在工作区之外、隐藏文件名或单独启动进程都不足以保证其不可读取或修改。真实隔离需要单独的操作系统身份或隔离环境、文件权限和必要的网络限制，并验证候选代码无法读取、修改或泄露私有材料。执行本身还必须防止不可信代码通过输出或外部通信泄露材料；本项目尚未建立该边界。

## 验收前置验证

1. 核验任务包来源、版本、基准提交、授权范围、依赖和公开测试，保存真实运行证据；未知项保持未知。
2. 对私有验收分别运行缺陷基准与已知正确版本，确认前者失败、后者通过，并覆盖正常行为；结果不公开测试源码或参考修复。
3. 检查修复端对私有材料的读取、写入和外传限制，以及候选代码运行环境的隔离；失败或无法确认时阻塞。
4. 测试补丁摘要或任务包版本不匹配、评测进程异常、超时、结果缺失及重复提交；这些情况不得产生通过结果。
5. 只有确定性检查、语义审查、适用环境证据和独立验收均满足规则，才允许正式结果事务写入与 Run 状态转换。

本文件描述目标和验收条件，不表示独立评测端、隐藏测试或操作系统级隔离已经存在。
