# DSH 小任务模板（历史参考）

用户已停止使用 DSH。下方任务字段可作参考，DSH 命令和权限模式是历史记录，不再作为当前协作方式；DeepSeek API 编码协作尚未接通。

按需填写，只提供当前步骤必需的信息；相关文件不足以解决问题时，可扩大阅读并在报告中说明原因。

```text
目标：<本次唯一小步骤>
验收：<可观察行为、失败或阻塞时的预期>
相关入口：<文件与函数；未知则写待定位>
修改范围与约束：<允许修改的范围、现有架构和安全边界>
测试：<专项测试与执行者；当前由 Codex 执行，DSH 编写测试>
已知失败：<准确错误、已尝试修复；没有则省略>

优先定向阅读，完成后自查 Diff；普通排查和简单修复在本步骤内连续完成。
不要输出凭据、隐藏用例或参考答案；不要提交、清理已有更改或迁移现有数据库。
报告实际修改、测试是否真正执行及结果、跳过项、限制和扩大阅读的原因；进度记录可先起草，Codex 核实后定稿。
```

Codex 用 `dsh headless --json` 下发任务并核对进程退出码及 final reason；不因为有输出就判断成功。简单修复可视上下文长度使用 `--session-id`，新功能或上下文过长时优先新会话。当前不擅自使用 `danger-full-access`；由 Codex 汇总专项失败交给 DSH 后复测。

后续任务尽量记录：DSH 墙钟耗时、模型步骤数、读取/搜索/编辑次数和启动次数；Codex 测试耗时、修复轮数、验收结果及跳过项。统计口径以实际事件和计时为准，不同工具的事件应按实际类型分类；取不到的数据记“未知”，重复读取只作为排查线索。事件日志可能含敏感内容，只记录汇总，不将原始日志、凭据或隐藏材料写入仓库。
