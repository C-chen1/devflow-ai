# DevFlow AI 一个月推进安排（暂定）

制定：2026-10-31。用户目标是争取一个月内完成剩余项目；已确认每天可投入 3–4 小时，按 30 天约 90–120 小时估算。本文是工作安排，不是完成承诺或新的架构规格；SPEC 仍是事实来源，PROGRESS 保存验证证据。

## 目标与范围

建议以 2026-11-30 前交付可演示、可评测的 V1 为冲刺主目标：Task/Run 链路、五角色、受控 Harness、基础 ContextBuilder、真实修复、失败恢复、人工处理、评测与交付。当前只有 Task 创建/查询/幂等及基础设施有实现和验证证据，执行主体尚未完成，排期存在实际工作量不确定性。

完整扩展范围仍包括长期记忆、冲突治理、跨任务召回、Skills 与受控 RSI，不删除或改名为已完成。这些内容全部在同一月完成目前不能保证；首轮 RSI 按既有顺序在工作包 E 与 SPEC §10.8 门槛满足后可先于完整记忆系统启动，不为赶日期绕过前置条件。

## 四周里程碑

- 第 1 周（11 月 1–7 日）：完成准入状态保护、Run 模型/迁移、RunCoordinator 和单 worker，验证原子领取、事务与创建幂等；交付从 Task 到 Run1 的可查询链路。
- 第 2 周（11 月 8–14 日）：建立必要执行记录和最小 Harness，覆盖角色权限、路径/命令约束、补丁、超时/进程清理及工具证据；用替身图验证路由和持久化顺序，开始接入真实 Agent 与基础 ContextBuilder。
- 第 3 周（11 月 15–21 日）：补齐五个真实 Agent、动态上下文及独立 Verifier；核验并运行首个真实任务，形成成功或失败的完整证据；推进 Policy 执行、失败分类、新 Run 恢复及人工处理。
- 第 4 周（11 月 22–28 日）：完成租约/心跳及并发故障验证、EvaluationRunner、诊断与评测报告；按 SPEC 扩展任务集与重复运行，整理 README、CI、Compose 和演示。首个 RSI 实验仅在 E 与版本/隔离/预算门槛已验收时启动。
- 11 月 29–30 日：修复阻塞、复现验收、补交付证据。未完成项照实保留，不用替身成功或单元测试结果代替真实修复/恢复/RSI 成果。

每周以实际验收调整下一周工作量；暂定里程碑不要求在教学上提前展开后续模块的全部设计。Memory/Skills/后续 RSI 继续按 SPEC F/G/H 验收，月底报告完成范围与剩余工作。

## 协作方式

按模块讲清用途、问题和层次，把相关关键边界合并核对；已验证概念不重复教学。学生明确要求代写时，AI 直接完成该范围代码及必要测试，再解释关键实现和验证证据；未授权实现仍由学生先尝试。事务、权限、生命周期和证据等关键设计不跳过理解验证。

当前继续准入条件更新与服务结果处理，不因新日程直接生成 Worker、Agent 或记忆模块。
